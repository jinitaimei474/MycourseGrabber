# jAccount 账号记忆实现计划

目标：用户在共享账号区填写一次并点击“记住账号密码”，后续冷启动自动填充；三个模块使用同一组输入，提供“忘记账号密码”。用户已明确要求持久化，采用 Windows 加密存储，无需额外询问实现细节。

方案：Electron 主进程 safeStorage 异步 API（Windows DPAPI），将整组账号密码加密后保存到 userData/credentials.json。相比明文配置或额外密码库，不引入依赖，也不保存解密密钥。只支持当前 Windows 用户解密；不可用时拒绝保存，允许临时输入继续使用。

边界：不读取真实用户凭据做测试，不打印密码；凭据不进入任务文件、普通状态广播或归档，不修改既有 Edge 会话。忘记会删除本应用凭据文件、清空输入和内存，不等同于退出网站。水源跳到 jAccount 时仅补全空字段，仍由用户完成认证；课程和网球维持原登录行为。保存失败保留上一条记录，损坏或不可解密时提示重新保存。

实施（按 writing-plans / test-driven-development 执行）：

- [x] 新增 credentials.cjs 与单元测试：加密保存、跨实例恢复、替换、清除、不可用/损坏/写入失败、输入校验。
- [x] 新增受来源约束的 load/save/forget IPC；普通 snapshot 只暴露保存状态与固定提示。初始化恢复到浏览器内存。
- [x] 共享账号区、保存/忘记按钮、重启一次性恢复，状态刷新不覆盖用户输入；连接时三个模块均取当前输入。
- [x] Electron 冷启动集成测试：真实 DPAPI，模拟凭据，保存→退出→重启→自动填充→忘记→重启为空；验证日志与配置不含明文及模块连接共用输入。
- [x] 更新使用说明与 1.6.0 版本，运行回归、构建新 EXE 并验证；不推送或发布新 Release。


## 验证记录（2026-11-02）

- 先后观察到预期失败：存储模块未实现、界面无记住按钮、水源未补全、错误消息截断泄漏长密码、忘记后遗留临时文件；实现后对应测试通过。
- 51 项桌面与 38 项共享核心单元测试通过；课程、论坛与网球的模拟浏览器/真实 Electron UI 回归通过。原网球浏览器夹具固定日期过期，改为未来日期，预约生产行为不变。
- 独立审查发现 Scheduler 重新登录 fill 超时可暴露密码；已在 fillCredentials 边界去除原始异常，并用真实 Edge 禁用密码框、真实 Scheduler 广播回归验证。复审无剩余阻断项。
- Windows safeStorage 使用虚构账号通过四次冷启动，覆盖默认不保存、主动记住、恢复、模块共用、状态脱敏、输入不被刷新覆盖、忘记后重启为空。
- 1.6.0 EXE 构建与包内 25 个源文件一致性验证通过；包内不含应用凭据、个人浏览器配置或测试目录。实际 EXE 的归档/检索/定位与凭据冷启动测试通过。
- 保留的限制：异常退出留下固定 .tmp 时会阻止保存，可点击忘记后重新保存；忘记不会退出既有网站会话。未读取或验证真实用户密码，未推送、合并或发布 Release。
