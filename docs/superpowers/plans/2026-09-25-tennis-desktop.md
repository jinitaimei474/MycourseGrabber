# 网球预约接入实施记录

目标：按用户确认的完整流程，在现有交大助手增加网球预约、微信支付二维码保存和付款提醒。

设计依据：`docs/tennis-source-analysis.md` 与用户 2026-09-25 的流程补充。每天北京时间 12:00 放号，提前七天；具体预约日期由用户填写，网站日期列表决定实际可选日期。首选和备选为有序的场馆、日期、单个时间段组合。默认不限小场地，可指定场地编号。生成二维码后等用户付款，不自动付款。

架构：新增 tennis/model.cjs（配置校验、日期、订单解释）、store.cjs（配置及账户日期锁）、adapter.cjs（真实页面导航和订单/二维码操作）、service.cjs（调度与恢复）；现有 main/preload/UI 接入第三模块，复用专用 Edge。独立 tennis.json 不含密码。IPC 只允许固定操作。二维码放在本机数据目录，通过受限图片数据展示及保存对话框导出。

执行：在现有工作区直接实施用户已经授权的功能，不另建工作区；不以用户示例截图生成实际订单。测试均拦截学校和缴费网址，正式预约只由软件中的启动操作触发。

- [x] 模型和持久化：先测试候选优先级、非法日期/时段、北京时间跨月放号计算、提交前锁定、重启保留锁、账号隔离，再实现。
- [x] 浏览器适配：复用登录、门户搜索、读取真实场馆和时段；正常页面提交条款、确认订单和支付流程。模拟页面覆盖不可预约、账户变化、默认微信、确认弹窗、二维码与有效期。
- [x] 调度：首选失败后备选、停止与截止时间、结果未知保留锁、待付款阻止重复、恢复已有订单付款、已付订单核实。
- [x] 桌面：候选编辑排序、放号默认时间可改、凭证输入、运行状态、二维码预览/导出、通知提醒、与旧模块互斥。
- [x] 验证：单元测试、模拟 Edge/Electron 全流程、既有课程与水源回归、构建 1.2.0、发布包冒烟及界面检查。

重点检查：超时不盲重试；跨账号不操作旧订单；付款网页只在已核实学校域名上操作；二维码到期不宣称成功；重启不自动运行。滑块等额外验证保留人工处理，再继续同一订单。在线订单列表不能完整读取时停止提交。

独立审查及修复：真实 Element UI 隐藏 checkbox 改为点击可见标签并核对勾选状态；SSO 完整重定向后的已登录页面视为就绪；无需网关的付款结果先查订单再确认成功。均先加入可复现失败的模拟场景，再修复通过。额外覆盖已支付时收起二维码、异步支付确认只点击一次、忽略已有不相关支付标签页。恢复支付总是从核实的学校订单重新进入。

验证记录：桌面单元 29 项及根目录课程 31 项通过；课程/水源/网球模拟 Edge 测试通过；三模块真实 Electron 界面测试通过。首次受限桌面测试发生调试连接断言，改在允许桌面访问的环境运行通过。旧课程 UI 测试的通用按钮选择器因新面板增加按钮而不再唯一，已限定在课程面板，回归通过。截图在 `artifacts/tennis-desktop-ui.png`，仅含模拟二维码。未提交真实预约，真实账户线上流程仍需使用时核验。

发布验证：1.2.0 构建成功。实际发布 EXE 已在隔离目录启动验证，三个模块、受限 IPC、密码输入类型、打包资源和已安装 Edge 启动检查通过。发布目录为 `desktop/release/1.2.0/SJTU-Assistant-win32-x64/`。
