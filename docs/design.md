# 交大定时选课初版设计

> 本文记录 v0.1 历史设计。v0.2 的多课程、结束时间和后台运行行为以 README.md 与 multi-course-plan.md 为准。

用户已授权读取当前登录页面、分析技术栈并制作初版。此目录原为空，不涉及已有代码或分支整合。

选择浏览器内 JavaScript 小面板，复用当前登录状态和学校原有按钮事件。其他方案为 Node.js + Playwright（需要浏览器调试端口或独立登录窗口），以及直接 HTTP 请求（必须维护动态参数、校验和会话）。当前初版以前者为最少安装步骤的实现。

源码已保存于 artifacts，仅本地使用，不纳入版本控制。主页面、动态 DOM 和核心 JS 都来自当前页面；未执行选课提交。CSS 用于理解结构，不复制为工具界面。

初版范围：用户自行查询并展开课程，小面板从页面读取教学班、教师、时间和内部标识。用户明确选中一个教学班，填写北京时间，默认只检查；正式模式定时刷新这个课程的教学班列表，满员等待，有余量时点击原始选课按钮。每轮串行，最短间隔 5 秒，最多 100 次、30 分钟。提交最多一次；响应丢失、弹窗或校验拒绝后停止。任何重启都由用户触发。

通过选课轮次、课程类别、学年学期和教学班 ID 锁定目标；若页面变化则停止。只在目标行自身与该课程已选列表核实已选状态。仅最终提交接口 flag=1/3/6 可判为服务器确认成功，不将前置检查的 flag=1 当作成功。

无后端、无需账户密码或导出 Cookie。浏览器关闭/刷新后任务失效；页面必须保持前台，电脑不可睡眠。定时依赖本机时钟及浏览器调度，不承诺毫秒精度。

验证：Node 内置测试验证时间、调度、停止、重试上限、提交去重和返回值；浏览器对导出 DOM 及实际页面做只读试运行。实际提交须等待用户指定目标与时间。
